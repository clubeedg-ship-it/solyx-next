## 1. Home (`/`) — "Explainer video"

**Current live markup:**
```html
<a href="#" class="hb-video-link">Explainer video</a>
```
(sits in `<p class="hb-video-wrap">`, under the "Bespaar, verduurzaam & verslim" hero section)

**Proposed target:** `/wp-content/uploads/2026/08/Solyx-Energy-Nijkerk-Solar-Iboost-Water-Accu-Besparend-Proces.2-1-1.mp4`

**Evidence:**
- `home.html` line 665: the same link originally opened a modal (`onclick="document.getElementById('videoModal')...`), and the modal itself (lines 1183–1190) reads *"De explainer video wordt hier binnenkort toegevoegd"* ("the explainer video will be added here soon") — confirms this was always meant to hold a real video, just not one that existed yet at prototype time.
- Live WP media library, queried via `GET /wp-json/wp/v2/media?media_type=video` (real browser navigation — plain `fetch()`/`curl` get redirected to `/.well-known/sgcaptcha/`): exactly **one** video exists site-wide — id 1382, `Solyx-Energy-Nijkerk-Solar-Iboost-Water-Accu-Besparend-Proces.2-1-1`, `source_url: https://2026.solyxenergy.nl/wp-content/uploads/2026/08/Solyx-Energy-Nijkerk-Solar-Iboost-Water-Accu-Besparend-Proces.2-1-1.mp4`.
- Verified live: loads fine as a `<video>` source, duration 12s, 852×480. The filename ("Besparend Proces" = "savings process") matches a short process/explainer clip.

**Confidence:** `likely` — it is the only video asset on the site and its filename matches the "explainer" intent, but nothing in the static source names this specific file, so it's an inference rather than a documented link.

## 3. `/besparen/` — "Hoe is dit berekend? →"

**Current live markup:**
```html
<a href="#" data-besparen-open="info">Hoe is dit berekend? →</a>
```
(inside `<p class="besparen-explain-link">`, under the savings sliders)

**Proposed target:** none — this is not a navigation link and should stay `href="#"`.

**Evidence:**
- `besparen.html` (lines ~2035–2043): this link is generated by `injectSliders()`, which sets `explain.href = '#'` and wires `explain.addEventListener('click', function(e){ openBdInfoSidebar(e); })` — by design it opens an in-page info sidebar (`#bd-info-sidebar`, populated with the "Hoe berekenen we dit?" methodology text), it never navigates anywhere.
- Live-tested directly (headed browser, real click, no data changed): the live page already carries this behavior — `document.getElementById('bd-info-sidebar')` exists, `window.openBdInfoSidebar` is defined, and clicking the actual `[data-besparen-open="info"]` link on `/besparen/` changes the sidebar's class from `besparen-sidebar ...` to `besparen-sidebar ... open` and its transform from `translateX(380px)` (off-screen) to `translateX(0)` (visible). **The link already works as intended.**

**Confidence:** `certain` — this was flagged by an automated `href="#"` scan, but it is a working JS panel toggle, not a dead link. No change needed.
